# v0.1.0 — the avatar renderer, packaged

**Release status:** prepared on 2026-09-28. The tag `v0.1.0` is cut from the
commit that adds this record, after a green dry run of the
[release workflow](README.md#how-a-release-is-cut) on `main`.

## Objective

The first release. It ships Renderer Phase 0 in full and Renderer Phase 1's
renderer work
([design policy §25](../design/DESIGN_POLICY.md#25-implementation-phases)),
and it publishes the `hydra` intent's package, so an OpenStrata Formation can
pin `hdToon` by digest beside the canonical `lookdev` runtime and
`usd-vrm-plugins`' `vrmImaging`. Until now every Formation pinned a package
built on one workstation, so none could be committed.

Renderer Phase 1 does not close with this release. Every item of it draws on
the avatar; what remains is the VRM host session as a Formation in this
repository, which pins published digests only and so follows this release
([vrm-host-session.md](../roadmap/vrm-host-session.md)).

## What ships

### The core and the Vulkan backend (Renderer Phase 0)

- **`RenderWorld`**: meshes, materials, textures, skins, poses and a
  `ToonView` camera, each advancing only its own revision, so a change
  re-uploads only what it touched. Extraction turns a commit into a
  `DrawList`. The public headers carry no OpenUSD, Hydra, Vulkan or windowing
  type, and a CTest holds them to it.
- **`Toon::OffscreenRenderer`**: one persistent Vulkan 1.3 renderer with
  dynamic rendering, Synchronization2 and one frame in flight on a timeline
  semaphore. Pipelines are created once, render targets reallocated only on a
  resize, and colour and depth read back at any extent.
- **Hosts**: `toon-headless`, which renders 1,000 frames on one renderer and
  writes the renderer evidence; the standalone `toon-viewport`, a scaffold
  that presents the bootstrap scene; and `usdview`.

### `hdToon`, the Hydra adapter

- Meshes, the camera and colour and depth AOVs, synced by dirty bit and drawn
  at the AOV's resolution. `UsdSkel` skinned meshes are read from
  usdSkelImaging's computations.
- A material Sprim per Hydra material: a prim with `vrmImaging`'s
  `vrm/mtoon` container selects MToon and is normalized into `ToonMaterial`;
  anything else is PreviewSurface. Value-only changes, which emulation never
  syncs, are taken from the terminal scene index, so an expression bake
  rewrites one parameter slot per time move and uploads nothing
  ([renderer report 11](../reports/renderer/11-2026-09-27-expression-bake.md)).
- Per-frame host evidence (`TOON_HYDRA_EVIDENCE`), which says in a `usdview`
  session how many materials selected MToon and what each frame uploaded.

### MToon on the avatar (Renderer Phase 1's renderer work)

- **`mtoon_opaque`**: lit and shade colours with shading shift and toony, GI
  equalization and emission, from one parameter slot per material
  ([report 07](../reports/renderer/07-2026-09-27-mtoon-opaque.md)).
- **Basic textures**: the base and shade colour textures through the mesh's
  UVs, with glTF's wrap modes and `KHR_texture_transform`, each image
  uploaded once with mipmaps
  ([report 08](../reports/renderer/08-2026-09-27-basic-textures.md)).
- **GPU skinning**: linear blend skinning in the vertex stage; a pose change
  writes each mesh's joint buffer and nothing else
  ([report 09](../reports/renderer/09-2026-09-27-gpu-skinning.md)).
- **Inverted-hull outline**: `mtoon_outline`, in world or screen units, with
  the outline width texture
  ([report 10](../reports/renderer/10-2026-09-27-mtoon-outline.md)).

On AliciaSolid in `testusdview`, with the published `vrmImaging` 0.10.0, all
20 draws are MToon and skinned, and 15 carry an outline
([report 12](../reports/renderer/12-2026-09-28-published-vrmimaging.md)).

### The release lane

A tag builds, tests, validates and packages the `hydra` intent on a hosted
Windows runner with the runtime, the Vulkan SDK and `ost` pinned by digest,
requires two packagings to give one archive digest, pushes the package to
GHCR and drafts the release ([how a release is cut](README.md#how-a-release-is-cut)).

## Compatibility

- **Platform:** Windows x86_64, MSVC. Linux is not measured; macOS is out of
  scope for the Vulkan-first phases
  ([design policy §4](../design/DESIGN_POLICY.md#4-backends)).
- **Runtime:** OpenStrata's canonical CY2026 `lookdev` runtime,
  `26.08-gl-windows-x86_64` (`sha256:b982656c…`): OpenUSD 26.08
  (`HD_API_VERSION` 98), Python 3.13 on the host.
- **GPU:** a Vulkan 1.3 device with `dynamicRendering`, `synchronization2`,
  `timelineSemaphore`, `shaderSampledImageArrayDynamicIndexing` and 128
  sampled images per stage.
- **`ost`:** 0.23.11 or newer to compose the package in a Formation; the
  release lane uses 0.23.13.
- **VRM materials:** need `usd-vrm-plugins`' `vrmImaging` in the session;
  without it every material is PreviewSurface. Measured with 0.10.0.

What each configuration was measured on is
[SUPPORTED_CONFIGURATIONS.md](../reference/SUPPORTED_CONFIGURATIONS.md).

## Known limitations at this release

Each is an accepted stand-in in the
[roadmap](../roadmap/current.md), replaced by the phase it names there:

- **Lighting** is one white key light fixed to the camera and a uniform
  ambient; scene lights are not read. Meshes without an MToon material draw
  flat.
- **Blend materials draw opaque.** Transparent MToon, rim, MatCap and UV
  animation are Renderer Phase 2.
- **Blend shapes are applied on the CPU** to a skinned mesh's rest points,
  and dual quaternion skinning runs the CPU kernel; both upload points.
- **Normals are derived**, never read; only a vertex or varying `st` is read.
- **Textures**: a fixed 128-entry table, trilinear sampling, and only the
  base, shade and outline width roles.
- **The Hydra path reads every frame back** into CPU buffers; there is no
  Hgi interop. Geometry is written on the render thread.
- **No picking** (the id AOVs are -1), no render tags, instancers or framing
  data window, and no lights.
- A world-coordinates outline ignores the stage's `metersPerUnit`.
- The standalone viewport draws only the bootstrap scene.
