# v0.3.0 — avatar animation fast path

The milestone that makes a continuously changing avatar the renderer's
first-class workload, and so `hydra-toon`'s most important one: a renderer
for continuously moving avatars rather than a general Hydra renderer
([design policy §2](../design/DESIGN_POLICY.md#2-core-concept), §11–§14).

**Done when**, measured in ordinary avatar motion, a pose, morph, expression
or camera change needs no scene rebuild, no pipeline rebuild and no full
geometry upload, and the telemetry below shows it in a report.

## Expression, look-at and camera fast paths

Connect the host's facial-expression, viseme and blink input to evaluated
renderer overrides, using the source owner's expression semantics rather
than defining them here. Verify ordinary avatar expression motion in the
dedicated viewport, including mapped inbetween weights and material values.
Look-at and the camera take a small-buffer route without Hydra's full scene
sync, with the same separation from structural state.

## Late motion latching

As far as it can go
([design policy §12](../design/DESIGN_POLICY.md#12-late-motion-latching)):

```text
Hydra scene sync → render world snapshot → draw list extraction
        ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
latest motion, expression, look-at, camera → GPU submit
```

so the motion sample on screen is as close as possible to the time it is
shown, not to the time Hydra evaluated. The latest pose arrives as
`usd-motion-plugins`' `MotionPose`
([integration scope §4](../design/INTEGRATION_SCOPE_POLICY.md#4-dependency-rules)).

## Latency telemetry

What an avatar renderer needs measured, beyond frames per second
([design policy §23–§24](../design/DESIGN_POLICY.md#23-performance-kpis)):

- pose update → buffer write, → submit, → present;
- expression update → submit;
- camera update → present;
- CPU and GPU frame time, and frame-time variance;
- the cost of joint-buffer writes, morph updates and material parameter
  updates;

and, in the end, when a motion sample was produced and when it reached the
display.

## Viewport animation and latency diagnostics

The dedicated viewport
([design policy §31](../design/DESIGN_POLICY.md#31-evaluation-hosts)) grows
what this milestone is judged with:

- expression mapping and material-value debugging;
- skeleton and joint display;
- the latency telemetry above, shown live.

## Fast and slow state kept apart

Topology, rest positions, UVs, textures, material structure and skin
influences change slowly; joint matrices, morph weights, expression values,
the camera and small material values change every frame. A fast change never
dirties slow state
([design policy §14](../design/DESIGN_POLICY.md#14-dirty-propagation)); the
telemetry is how this milestone shows it.
