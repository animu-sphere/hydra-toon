# v0.3.0 — avatar animation fast path

The milestone that makes a continuously changing avatar the renderer's
first-class workload, and so `hydra-toon`'s most important one: a renderer
for continuously moving avatars rather than a general Hydra renderer
([design policy §2](../design/DESIGN_POLICY.md#2-core-concept), §11–§14).

**Done when**, a representative VRM avatar's ordinary pose, morph, expression,
look-at and camera changes use the existing renderer fast path through a
`usd-avatar-runtime` evaluated-state adapter, without scene or pipeline rebuilds
or full geometry uploads. Reports must establish Hydra/direct parity and
producer-to-submit/present-API-return timing on the dedicated Vulkan viewport.

This milestone closes the renderer's integration boundary and evidence. It
does not require the whole avatar runtime, full MMD evaluation, OpenExec,
WebGPU, multi-avatar scheduling or a stable renderer C ABI. The runtime's
contracts and implementation are owned by its
[roadmap](https://github.com/animu-sphere/usd-avatar-runtime/blob/main/docs/roadmap/current.md).

## Evaluated-state adapter and representative-avatar evidence

The optional adapter accepts separate canonical base RGB and scalar alpha via
explicit `BaseColorRgb`/`Alpha` bindings, with independent override release and
overlap rejection. The runtime's
[scoped motion-check host](https://github.com/animu-sphere/usd-avatar-runtime/blob/main/docs/architecture/OUTPUT_PATHS.md#scoped-toon-transport-check)
now exercises installed consumer transport with real-owner values and generated
probe resources. The Hydra delegate now describes an actual avatar's resident
mesh/material paths, palette joint identities, inverse binds, placement and
subshape slots
([renderer report 43](../reports/renderer/43-2026-10-10-hydra-resident-targets.md)).
A renderer-built host matcher pairs runtime identities with that description
and binds a whole avatar's skins and shapes from a layout following the
runtime binders' conventions
([renderer report 46](../reports/renderer/46-2026-10-10-avatar-target-matching.md)).
An opt-in host now links the runtime's real VRM expression/LookAt providers.
Every output of a committed fixture and of two local avatars matches and
binds. Each result's fast output equals the same values composed by
UsdImaging and usdSkelImaging from a session-layer oracle, in state and in
offscreen colour/depth, with bone and expression gaze, an inbetween and MToon
colour binds
([renderer report 47](../reports/renderer/47-2026-10-11-avatar-real-providers.md)).
`emissiveFactor` binds scaled by the resident material's `emissiveStrength`,
as the delegate realizes it
([renderer report 48](../reports/renderer/48-2026-10-11-avatar-emissive-factor.md)).
The dedicated viewport now hosts the same providers: results published
after a frame's extraction reach it at the late read, through instance
resets and scene replacement, with no static upload or Hydra sync, and a
panel associates the runtime frame and its source names with the bound
targets
([renderer report 49](../reports/renderer/49-2026-10-11-viewport-avatar-runtime.md)).
Both hosts also compose the runtime's motion clip provider ahead of the
VRM provider: a committed clip and seven VRMA clips on two local avatars
match UsdImaging's palettes and images, and pose the viewport through late
reads
([renderer report 50](../reports/renderer/50-2026-10-11-avatar-motion-provider.md)).
Material binds are
established on the committed fixture; on a real avatar they wait for one
that binds material colours, and parity with the runtime's own Hydra
publication waits for that publication
([not yet in a milestone](README.md#not-yet-in-a-milestone)).

Validate the consumer contract with real `usd-avatar-runtime` providers and
extend the optional adapter's material mappings for their canonical outputs.
Prepare runtime-to-resident bindings in the external host by matching the
runtime's target identities to the described resident identities, listing
each shape's described subshape slots so the adapter interpolates its
inbetweens. The runtime assigns this matching to a renderer-side host
([resident target matching](https://github.com/animu-sphere/usd-avatar-runtime/blob/main/docs/architecture/OUTPUT_PATHS.md#resident-target-matching));
keep runtime and format types out of core/backend headers
([integration scope §4](../design/INTEGRATION_SCOPE_POLICY.md#4-dependency-rules),
[placement rules](../architecture/PROJECT_LAYOUT.md#3-where-new-code-goes)).

Renderer code consumes those results without invoking evaluators. The
static asset may be prepared through Hydra; a general Hydra-free asset loader
is not required here.

## Release

Every acceptance section of this milestone has its evidence: the Hydra/direct
parity of draw packets, pipelines, values and images with structural
rebinding, generated-source ages at every endpoint to present API return, and
the fast/slow and build-independence records
([renderer report 51](../reports/renderer/51-2026-10-11-v030-evidence.md)).
What remains is the release itself: its record, the changelog's version and
the package.
