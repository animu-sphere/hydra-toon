# Generated MMD/Jolt resident deformation and UV composition

Date: 2026-10-26. Renderer base `19e1a3d` plus this change; MMD checkout
`22219c6`, runtime checkout `a76aaf4` and compatible local installed packages.
Windows x64, MSVC 19.51 Release, OpenUSD 26.08, runtime ABI 5, Jolt 5.5.0
and Vulkan. Generated resources only. Continues
[report 105](105-2026-10-26-mmd-resident-uv.md).

## Boundary

`TOON_MMD_AVATAR_PROVIDER_TEST` adds an uninstalled test host using installed
`AvatarRuntime` component `mmd` and `physicsJolt`. Its canonical model and bound
motion run owner control through runtime pre/post continuations. A two-joint
rig combines a keyed root with a mode-1 dynamic child. The runtime world
callback alone steps a contact-free Jolt body with gravity and initial velocity;
the MMD owner converts completed body transforms into final joint feedback.
The renderer consumes the final retained snapshot and never steps physics.

One resident GPU-skinned mesh has a reversed joint palette, a sparse vertex
morph, primary UVs, edge scales and an additional static UV stream. Nested
groups reach vertex and UV leaves. Automatic matching binds all skin, morph
and UV output, including reordered runtime UV slots. UV tangent regeneration
expands skin influences and sparse morph ranges across new seams.

## Evidence

- Six frames over three reset generations exercise group weights
  `0 -> 1 -> 1.5 -> -0.5 -> 0 -> 0`, collapsed UVs and restored UV/vertex
  bases while the dynamic body continues moving. Runtime frame/generation
  metadata and exact solver replay are checked after each world reset.
- Independent root keys, expected UV/vertex weights and direct solver readback
  check the final runtime values. The USD/Hydra oracle authors those independent
  inputs into a generated SkelAnimation and `st`, rather than copying runtime
  final joints or renderer palettes. Rest geometry, topology, normals, UVs,
  tangents, skin influences, sparse morph data and auxiliary streams agree.
  Final palettes agree within `2e-6` per component.
- Textured MMD and normal-mapped MToon Vulkan colour and depth agree exactly
  with that oracle at 128 by 128, 1x/4x MSAA. Geometry covers pixels, ongoing
  physics changes the zero-morph frame, and removing either skin or vertex
  morph changes pixels with the other streams held fixed. World reset
  reproduces each frame's original pixels. Steady draws reuse geometry and
  pipelines with no validation messages.
- Duplicate snapshots reuse pose, morph, UV and tangent arrays. First-generation
  snapshots/palettes survive producer destruction. Release restores all
  immutable resident pose, morph, UV and tangent values.

The seven focused CTests pass: new MMD-avatar CPU/GPU, existing MMD-UV CPU/GPU,
Hydra primvars CPU/GPU and Hydra skinning. Documentation checks pass.

## Reproduction and limits

Reuse report 105's configured Hydra build and installed runtime/MMD/physics
prefixes. From an initialized x64 MSVC developer shell, set `Jolt_DIR` to the
SDK used to build the installed physics backend:

```powershell
cmake -S . -B build/avatar-state-hydra -DTOON_MMD_AVATAR_PROVIDER_TEST=ON `
  "-DJolt_DIR=<compatible-jolt-sdk>/lib/cmake/Jolt"
cmake --build build/avatar-state-hydra --target toon-hydra2-mmd-avatar-test toon-hydra2-mmd-uv-test toon-hydra2-primvar-test toon-hydra2-skinning-test toon-renderer-shaders --parallel 2
ctest --test-dir build/avatar-state-hydra `
  -R '^toon-renderer-(mmd-(avatar|uv)-(cpu|gpu)|hydra-(primvars(-gpu)?|skinning))$' --output-on-failure
```

This establishes combined generated deformation/physics/UV composition. It
does not read PMX/VMD, discover application participants, validate contacts or
constraints, perform material morphs, publish additional runtime UV channels
or establish representative avatar L3 acceptance. Full asset playback and
resident application lifecycle remain open. No production renderer algorithm,
owner/runtime API, importer or dependency pin changed; optional format/solver
dependencies remain confined to the test host.
