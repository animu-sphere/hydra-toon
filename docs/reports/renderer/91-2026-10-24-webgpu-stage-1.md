## TL;DR

**Stage 1 is in. `Toon::WebGPU` renders the unlit mesh pipeline and
PreviewSurface offscreen through Dawn's Direct3D 12 adapter, and through
its Vulkan adapter on request, from the same extracted `DrawList` as the
Vulkan backend, with its products, statistics and late-frame source. The
shaders moved to a root `shaders/` grouped by role, each backend's
resources behind a bindings module selected by a define (WGPU-Q2); every
generated WGSL module passes Tint during the build, uniformity included.
On nine canonical scenes over both background modes the two backends'
images are identical but for one channel of one textured pixel at one
step, depth and coverage identical; through Dawn's Vulkan adapter all
eighteen are identical. WGPU-Q1's limits follow: unlit exact, lit and
textured within one step with no pixel beyond it. The PreviewSurface GPU
checks, CPU oracles and upload counters included, pass on WebGPU
unchanged. Dawn's Direct3D 12 device needs DXC at run time, which its
release lacks; a pinned DXC release supplies `dxcompiler.dll`.**

## 1. Shaders at the root, and the bindings modules

`backend/vulkan/shaders/` moved to `shaders/` with its history, grouped by
role at the user's request: `bindings/`, `common/` (skinning, the surface
stage and lighting), `scene/` (unlit mesh, shadow casters), `preview/`,
`mtoon/`, `mmd/`, `present/` and `webgpu/`. Basenames are kept, so every
compiled artifact keeps its name and `SceneShadersIn` is unchanged.
Includes are root-relative (`common/skinning.slang`) and `slangc` gets
`-I shaders`.

Resource declarations moved into `bindings/bindings_vulkan.slang` and
`bindings/bindings_webgpu.slang`, which `bindings/bindings.slang` selects
by `TOON_WEBGPU` and `common/skinning.slang` includes first. Each states
the draw constants' binding, every buffer's binding as a macro the shared
modules declare with, and three accessors:

| Accessor | Vulkan | WebGPU |
| --- | --- | --- |
| `SampleRole(role, entry, sampler, uv)` | `textures[entry].Sample(samplers[sampler], uv)` | white for entry 0, else a `switch` on the role over nine role textures and their own samplers |
| `SampleRoleLevel(…, level)` | `SampleLevel` alike | alike |
| `GatherShadow(uv, layer)` | `shadow_map.Gather(samplers[4], …)` | `shadow_map.Gather(shadow_sampler, …)`, a non-filtering sampler, as depth32float requires |

Every texture read in MToon, MMD and PreviewSurface now names its role
(`kMToonBase` … `kMToonShift`, `kMmdBase`/`Sphere`/`Toon`, PreviewSurface's
input index), so Vulkan's SPIR-V reads the same table as before. WGPU-Q2 is
settled by this: a define keeps one `slangc` invocation per entry point,
and nothing needed Slang's link-time modules.

With these bindings, the nine scene modules' 18 entry points generate WGSL
that Tint accepts, uniformity analysis included, except MMD's two surface
vertex stages, whose output struct still lacks explicit locations (report
90); the presentation pair, overlay and composite, was not regenerated
here. That the PreviewSurface and
MToon fragments pass uniformity unchanged follows from the modules'
existing rule that every implicit-derivative sample precedes divergent
control flow, and from WGSL treating read-only storage and uniform loads
as uniform. No `derivative_uniformity` relaxation was needed.

`toon_add_shader_library` gained a `WGSL` mode: `slangc -target wgsl
-DTOON_WEBGPU` writes `<module>.<stage>.wgsl.unchecked`, `tint
--input-format wgsl --format wgsl -o NUL` must accept it, and only then is
it renamed into place, so a rejected module fails the build and leaves no
output that looks current. The WebGPU build compiles `mesh`,
`preview_surface` and the backend's own `webgpu/mipmap`.

## 2. The backend

`backend/webgpu/` builds `toon-render-webgpu` (`Toon::WebGPU`) from three
files over `webgpu.h`: `webgpu_device.cpp` (instance with timed waits,
adapter, device, futures, readback maps), `webgpu_scene.cpp` (layouts,
pipelines, texture, material and mesh caches, recording) and
`webgpu_backend.cpp` (the `OffscreenRenderer`). `include/toon/webgpu_backend.hpp`
adds `WebGpuShaders`, `WebGpuAdapter`, `ProbeWebGpuBackend`,
`CreateWebGpuOffscreenRenderer` and `RenderWebGpuOffscreen`, and joins the
boundary check's list.

| Policy | What stage 1 does |
| --- | --- |
| §2 adapter | `WGPUBackendType_D3D12`, high performance, core feature level; `WebGpuAdapter::Vulkan` for diagnosis. A returned adapter of another kind is a skip. WebGPU defaults: no limit raised, no feature required |
| §4 group 0 | frame buffer, the shadow views' image (`texture_2d_array`, unfilterable), their parameters, a non-filtering gather sampler |
| §4 group 1 | per material: the PreviewSurface buffer at binding 2, nine role textures (3–11) and samplers (12–20), an absent role bound to a 1 × 1 white; rebuilt only when a role's view or sampler, or the grown buffer, changes. A draw with no material binds one display group |
| §4 group 2 | influences, joints, morph offsets, ranges and weights, uploaded and rebound as the Vulkan mesh cache does; an undeformed group of one identity matrix otherwise |
| §4 group 3 | `DrawConstants` at a dynamic offset, 256-byte stride, in one uniform ring written once per frame, before submission |
| pipelines | WebGPU has no dynamic cull mode, front face, depth writes or vertex strides, so each combination a draw needs is created on first use and kept; a missing UV or tangent stream binds one zero element at stride 0 |
| §6 upload | geometry and parameter slots by queue writes on revision changes; textures by `wgpuQueueWriteTexture`, every level below the first drawn from the one above by `webgpu/mipmap.slang`, sRGB through sRGB views |
| §6 readback | colour and depth copied to mappable buffers at a 256-byte pitch and repacked to the products' pitch, origin top left |
| §6 late latch | the same `LateFrameState` reading as Vulkan's, after the previous frame and before the fast writes |
| clip space | `WebGpuClipFromWorld` maps z to [0, 1] and leaves y alone: WebGPU's normalized device y points up. Front faces stay counter-clockwise |
| validation | Dawn's uncaptured errors are counted as validation messages; a lost device fails the frame with Dawn's reason |

Not in stage 1, each failing or reported rather than approximated: every
request renders at one sample (`statistics().samples` says 1); a draw
whose material is MToon or MMD fails the frame naming stage 2; no shadow
view is drawn, so every light's view slot is 0 and receivers see none. The
backend duplicates the Vulkan backend's frame rows, PreviewSurface slot
writer, view-row and UV-row helpers and transparent ordering, since a
backend may not depend on another ([layout §4](../../architecture/PROJECT_LAYOUT.md#4-dependency-directions));
each copy says so.

## 3. Dawn needs DXC

The first run failed device creation on Direct3D 12:

```text
Dawn could not create a device on NVIDIA RTX A5000: DynamicLib.Open: dxcompiler.dll Windows Error: 87
    at EnsureDXCLibraries (…\src\dawn\native\d3d12\PlatformFunctionsD3D12.cpp:224)
```

Dawn's Direct3D 12 backend compiles its HLSL with DXC by default and loads
`dxcompiler.dll` from the executable's directory; the release archive has
none. With the Vulkan SDK's, the Windows SDK's (with `dxil.dll`) or the DXC
release's `dxcompiler.dll` alone beside `toon-headless`, all seven
evidence checks pass. Disabling the `use_dxc` toggle for FXC would have
changed a Dawn default without need ([policy §2](../../design/WEBGPU_POLICY.md#2-implementation-and-acquisition)).
The project chose the release pin: `v1.9.2609`, the newest stable release
at least two weeks old, its archive hashed like Dawn's, and only
`dxcompiler.dll` copied and installed, under its LLVM and MIT licences.
Microsoft's `dxil.dll` is not needed and is not redistributed.

Dawn's static library carries more than Dawn: its symbols include Abseil,
SPIRV-Tools (with SPIRV-Headers' grammar), Vulkan-Utility-Libraries over
Vulkan-Headers, and PartitionAlloc. `third_party/dawn/` holds Dawn's
licence and each of theirs at the revision Dawn's `DEPS` pins, installed
under `share/toon/licenses/dawn`.

## 4. Evidence

**Headless.** `toon-headless --backend webgpu` renders the bootstrap
triangle 1,000 times at 64 × 64 on one renderer:

| Check | D3D12 | Vulkan adapter |
| --- | --- | --- |
| `renderer.backend.capability` | pass, "Dawn Direct3D 12 adapter: NVIDIA RTX A5000" | pass |
| `renderer.gpu.frame` | pass | pass |
| `renderer.validation.messages` | pass, 0 errors | pass |
| `renderer.render_product.color` | pass: the CPU BRDF oracle's centre pixel within 2 steps | pass |
| `renderer.render_product.depth` | pass | pass |
| `renderer.frame.persistence` | pass: 1 pipeline, 1 target allocation, 1 topology and 1 point upload over 1,000 frames | pass |

The report's device reads `"backend":"webgpu"`, `"api_version":"WebGPU
(Dawn, Direct3D 12)"`, `"driver_version":"D3D12 driver version
32.0.15.9716"`. The checks later stages bring report skip, naming the
stage. `toon-headless.exe` is 11.3 MB with Dawn linked statically;
`dxcompiler.dll` is 22.3 MB.

**PreviewSurface checks.** `validation/preview_surface_test.cpp` now takes
a renderer factory, and `toon-preview-surface-webgpu` runs its 1x half on
WebGPU: constant emission, the normal-incidence and grazing BRDF against
CPU values, Mask's threshold and depth, Blend over the background, packed
texture channels, sRGB decoding, the UV fallback, USD's bottom-left origin
under rotation and translation, culling, the bound unlit fallback, the
display colour under key and ambient light, and normal maps with
derivative, mirrored, rotated and authored frames against CPU-baked
normals, with the upload, slot-write and pipeline counters each edit must
leave. All pass unchanged.

**Parity.** `toon-webgpu-parity` renders each scene through a fresh
Vulkan and WebGPU renderer at 128 × 128, one sample, shared shadows off,
over the opaque and transparent clears, and compares every channel:

| Scene | Covered pixels | D3D12: largest, pixels > 1 | Vulkan adapter |
| --- | --- | --- | --- |
| unlit (diagnostic sphere and floor) | 10,102 | 0, 0 | 0, 0 |
| display colour (unbound sphere) | 6,642 | 0, 0 | 0, 0 |
| PreviewSurface dielectric | 6,642 | 0, 0 | 0, 0 |
| PreviewSurface metal | 6,642 | 0, 0 | 0, 0 |
| scene point, spot and ambient lights | 9,572 | 0, 0 | 0, 0 |
| receding sRGB checker, every mip level | 10,368 | 1 (one channel of one pixel), 0 | 0, 0 |
| normal map, derivative frame | 6,642 | 0, 0 | 0, 0 |
| texture-alpha Mask | 5,230 | 0, 0 | 0, 0 |
| layered Blend spheres | 2,296 | 0, 0 | 0, 0 |

Each row holds for both clears; coverage and depth are identical in every
row, and no validation message was raised on either backend. Identity is
not required (§9), and on another vendor's driver or with multisampling it
is not expected; but on this machine the two compilers' arithmetic and the
two drivers' rasterization and filtering agree to the bit almost
everywhere, so any wider limit would hide a real difference. WGPU-Q1 is
therefore: unlit exact; lit and textured at most one step, no pixel more
than one step apart; coverage identical; depth within 1e-6. A later class
gets a limit of its own only with a report that explains why.

An early run reused one renderer pair across scenes and drew stale meshes:
each scene's `RenderWorld` numbers meshes and revisions from 1, which a
renderer that drew another scene takes for resident ones. The test now
creates its renderers per scene; `PresentSession::ResetScene` exists for
the same reason on a presentation session.

## 6. What remains

Stage 2 brings MToon and MMD on the per-material bind groups this stage
built for PreviewSurface (MMD's vertex interface first needs explicit
locations), 4x with sample-mask Mask coverage and a depth resolve, and
evidence for skinning, morphs and late latch, whose buffers and source
are already bound. Whether the duplicated frame and slot writers move to
a shared, backend-neutral place is a layout decision for stage 2, when
the MToon and MMD writers would otherwise be copied too.
