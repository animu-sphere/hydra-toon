# v0.3.0 evidence: packets and rebinding, every latency endpoint, fast and slow state

- Date: 2026-10-11
- Machine: Windows 11 x86_64, NVIDIA RTX A5000; MSVC 14.51 / Visual Studio 18
- Runtime: as in [report 50](50-2026-10-11-avatar-motion-provider.md)
- Scope: the parity, latency and fast/slow sections of
  [v0.3.0](../../roadmap/v0.3.0.md)

## The gap

Reports 47 to 50 compared palettes, weights, materials and images with the
oracle, but not which draw packets each path produced or which pipelines
they selected. Nothing replaced a scene under a binding. The viewport
measured expression and gaze input only to submit, and pose input from
buffer write onward. The fast/slow and build-independence evidence of
earlier reports predates the runtime hosts.

## Change

- **Draw packets.** For every result, the provider check extracts both
  outputs' draw lists. Each must hold the same meshes in the same order,
  with the same material and the same pipeline selection: shading model,
  alpha mode, transparency, hull, sidedness, skinning and morphs.
- **Rebinding.** After its frames, the check builds a second Hydra scene
  over the same stage, as a host replacing a scene does, and states a new
  epoch. The old binding must refuse a result over it. The replacement is
  then matched and bound, and one more result must match the oracle.
- **Latency.** The viewport's telemetry now ages pose, expression and
  look-at input at each endpoint: the late read, the buffer write, submit
  and present API return. These are `*_latch`, `*_buffer`, `*_submit` and
  `*_present_api`; camera input keeps its present endpoint. Only the first
  frame after an input update counts, as before. A held result keeps its
  input's original time. `toon-late-frame-state` looks the series up by name
  and checks every endpoint.
- **Overrides.** While the avatar runtime drives the scene, the Morphs and
  Materials panels' overrides are ignored, with a note on the overlay. The
  runtime binds over the unoverridden scene, and an override would make the
  adapter refuse it.

## Evidence

### Parity

All five provider CTests pass. Each compares 18 results plus the rebound
one. The 2 draw packets of the fixture are identical on both paths in every
result. The replacement scene is refused in epoch 2 until it is bound. It
then binds 2 skins and 6 morphs and matches the oracle. Palettes, weights,
materials and images are as reports 47 to 50 state.

### Latency

The two local avatars ran hidden with vsync on for 600 frames each. The
runtime's motion provider played `VRMA_01`, and expression and gaze input
was generated, stamped as it was made. All times are generated-source ages
in milliseconds at p50 / p95:

| Run | Late | Sample to publication | Latch | Buffer | Submit | Present API |
| --- | --- | --- | --- | --- | --- | --- |
| `AliciaSolid`, 120 results/s | 596 of 600 | 0.30 / 0.42 | 3.33 / 8.21 | 3.37 / 8.26 | 3.75 / 8.63 | 3.78 / 8.65 |
| `AliciaSolid`, 30 results/s | 296 of 600, 304 held | 0.43 / 0.63 | 4.69 / 9.35 | 4.74 / 9.42 | 5.08 / 9.91 | 5.11 / 9.94 |
| `Seed-san`, 120 results/s | 596 of 600 | 0.33 / 0.48 | 7.21 / 8.69 | 7.26 / 8.75 | 7.66 / 9.22 | 7.70 / 9.27 |

Expression and look-at ages coincide: one generated frame carries both. At
30 results per second, 304 late reads reapplied a held result. Only the 299
first frames after a new input counted as responses, each aged from its
original time. The frame interval was 16.6 ms at p50. Pose input stayed
unmeasured: a clip pose has a clip time, not a production time.

### Fast and slow state

In every viewport run here and in reports 49 and 50, the evidence is:

- one Hydra sync per scene;
- no static upload after the first frame;
- every late read applied, none rejected.

Writes followed the motion. `AliciaSolid` at 120 results per second wrote
11,920 joint and 2,089 weight updates and no material. The adapter applies a
result only over a scene whose static arrays, revisions and material
structure equal the bound scene's. So each accepted application also shows
that no slow state changed. Replacing a scene is the structural case: the
replaced scene is refused until rebound in a new epoch, in the check and in
`toon-viewport-avatar-runtime-thread`.

## Commands and limits

```powershell
ctest --test-dir build/avatar-viewport   # 64 of 64
toon-viewport-avatar --usd <avatar> --avatar-runtime --avatar-rate 120 `
    --avatar-motion <clip.vrma> --telemetry-output latency.json
```

Present API return is not scanout, and no display time was measured. The
input is generated, not captured; a connector's input would be aged from
its receipt.
