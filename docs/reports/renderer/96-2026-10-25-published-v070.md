## Release lane and artifacts

The [dry run on main](https://github.com/animu-sphere/hydra-toon/actions/runs/40158317945)
and the [tagged release workflow](https://github.com/animu-sphere/hydra-toon/actions/runs/40158901159)
both completed all four jobs successfully. Tag `v0.7.0` names
`0e6399ce62c87f96d181bdbdddcc10b4c0c2dea5`.

All six [release assets](https://github.com/animu-sphere/hydra-toon/releases/tag/v0.7.0)
were downloaded from the published release: the source archive, renderer
archive, manifest, SPDX SBOM, pin table and `SHA256SUMS`. Every checksum
matches. The manifest lists 68 files, among them `hdToon.dll`, its
registration, `toon-headless.exe` and all 22 scene SPIR-V shaders, both in
`bin/shaders/` and beside the plugin. Its provenance names the release
commit, `refs/tags/v0.7.0` and the release workflow. The source archive
holds the same 356 files as the tag's tree, allowing Windows checkout line
endings.

Against the published v0.6.0 manifest ([report 89](89-2026-10-24-published-v060.md)),
four files are added and none removed: the backend-neutral
`include/toon/backend.hpp`, the shared CPU writers'
`lib/toon-render-backend-shared.lib`, and the two WebGPU public headers
`include/toon/webgpu_backend.hpp` and `webgpu_present.hpp`. Those headers
include only standard and `toon` headers; no Dawn, DXC or WGSL file is in
the package, as report 95 recorded for the local package. Ten of the 22
SPIR-V shaders differ in bytes from v0.6.0's (MMD, MToon, PreviewSurface and
shadow stages), from the shader reorganisation and the shared bindings; the
frames below are unchanged.

## Published Formation and headless GPU checks

[`formations/vrm-host-session/`](../../../formations/vrm-host-session/)
now pins that archive beside the unchanged published runtime and
`vrmImaging` 0.10.0; it pinned v0.6.0 until now. Its regenerated lock
contains no workstation path. From the Formation directory, with host
Python 3.13 on PATH:

```sh
ost formation lock formation.toml
ost formation doctor formation.toml
ost formation run formation.toml
ost formation run formation.toml -- toon-headless --report <local report path>
```

Doctor passed resolution, lock, environment and command reachability.
The declared probe command exited zero with `HdToonRendererPlugin`, one
MToon material, one PreviewSurface material, four samples and nine
pipelines; the probe stage has no mesh, so it draws nothing.

The published headless runner exited zero on the RTX A5000: 31 PASS,
six SKIP and zero FAIL, with the same check identifiers and outcomes as
v0.6.0's run in report 89. Vulkan validation reported no messages. The six
SKIPs are the install-tree and Hydra discovery/delegate/buffer/host
assertions, which are CTest checks rather than this headless runner's work.

## Representative avatars from the published renderer

Each comparison draws the same stage through `testusdview` with the
published v0.7.0 package and compares it with report 89's captures from the
published v0.6.0 package, through the same drivers, cameras and settings.
Every Formation here pins the same published runtime and imaging package and
differs only in the `toon` digest.

**MMD.** 布伦妮 through report 63's reference-shot script at its face,
turned face, bust and full body, 1,920 × 1,080, 4x, with `toon:shadows` on
and off. All 8 PNGs are byte-identical to v0.6.0's. The evidence reads
`draws_mmd=22 draws_mmd_outline=13 draws_mmd_shadow=19 shadow_views=1
draws_shadow=19`.

**MToon.** AliciaSolid (VRM 0.x) and the VRM 1.0 constraint sample, with
[report 32](32-2026-10-04-vrm-reproduction.md)'s full-body and close-up
cameras, 800 × 900, 4x, authored normals, `toon:shadows` on and off. As in
report 89, raw VRM ingestion appends the matching local `usdVrmFileFormat`,
`usdVrmPackageResolver` and container libraries to the exported Formation
environment. All 16 captures exited zero, asserted the MToon, draw, sample,
extent and authored-normal counts, and are byte-identical to v0.6.0's.

The Vulkan backend's frames are therefore unchanged across the WebGPU
milestone on these assets, as the v0.7.0 record states. Captures, evidence
and logs stay under the ignored `build/v070-published-gpu/`; the models are
not redistributable.

WebGPU backend is not in the published package and is not exercised here;
its evidence is [report 94](94-2026-10-25-webgpu-acceptance.md). No new
scene, asset, pose or motion coverage is added beyond report 89. Linux,
macOS and other GPU vendors remain unmeasured.
