## Published Formation and headless GPU checks

[`formations/vrm-host-session/`](../../../formations/vrm-host-session/)
now pins that archive beside the unchanged published runtime and
`vrmImaging` 0.10.0; it pinned v0.2.0 until now. Its regenerated lock
contains no workstation path. From the Formation directory, with host
Python 3.13 on PATH:

```sh
ost formation lock formation.toml
ost formation doctor formation.toml
ost formation run formation.toml
ost formation run formation.toml -- toon-headless --report <local report path>
```

Doctor passed resolution, lock, environment and command reachability.
The declared probe command exited zero with `HdToonRendererPlugin`, one
MToon material, one PreviewSurface material, four samples and nine
pipelines; the probe stage has no mesh, so it draws nothing.

The published headless runner exited zero on the RTX A5000: 31 PASS,
six SKIP and zero FAIL. Beside v0.2.0's frame, MToon, lighting, outline,
MSAA and skinning checks, the MMD material, morph, outline and self-shadow
checks and the four shared-shadow checks (`shared_casters`, `receivers`,
`views`, `cross_family`) passed. Vulkan validation reported no messages.
The six SKIPs are the install-tree and Hydra discovery/delegate/buffer/host
assertions, which are CTest checks rather than this headless runner's work,
as in [report 33](33-2026-10-04-published-v020.md).

## Limits

This run verifies the published Windows package on one NVIDIA GPU. It adds
no new scene, asset, pose or motion coverage beyond reports 85 to 87; the
viewport is not part of the `hydra` package, so its fast-path frames and
the bounded cost fixtures remain report 87's preparation evidence. The
published v0.3.0, v0.4.0 and v0.5.0 packages were not Formation-checked
after publication and are not checked here; v0.6.0 supersedes them. Linux,
macOS and other GPU vendors remain unmeasured.
