## Fixed fixture set

`validation/rgba_fixture_test.cpp` creates two original Apache-2.0 fixtures,
without a model download or format plugin:

1. An octahedral MToon head and dress with an inverted hull, eight thin
   textured Blend hair strands, a textured Mask ribbon, an emissive badge
   and a normal-mapped PreviewSurface swatch.
2. An MMD receiver and displaced caster, with the shared toon ramp and
   self-shadow. Disabling self-shadow must brighten the shadowed centre by
   more than 40 byte levels while preserving every alpha byte; both casters
   must have drawn. This is the analytic scene from report 60 at a larger
   extent, with transparent output rather than an opaque clear.

Each renders at 256x256, actual 1x and 4x MSAA, with transparent clear, native
opaque black/white controls and a final return to transparent with a different
background setting. Returned foreground bytes must be identical. The avatar's
outline-disable control must change the product. Every case contains both
empty and opaque alpha, and 4x cases require partial coverage. The existing
analytic `toon-rgba-output-gpu` remains the independent oracle for surface,
hull, Mask/A2C and layered Blend alpha; the new test does not replace it.

`scripts/check_rgba_fixtures.py` uses the existing independent standard-library
PNG decoder to check the production export conversion. It preserves alpha,
requires zero RGB at zero alpha, decodes straight sRGB and premultiplies in
linear space. For each foreground it evaluates source-over on black, white,
an odd-cell checkerboard and an original asymmetric procedural RGB8 image
(decoded from sRGB before use). It saves 16 local opaque PPM composites for
inspection. The black/white equations are independently checked against
native opaque renders. Checker/image composition is a CPU consumer; it is
not a claim of image-background support in the viewport. The existing
viewport test independently covers GPU solid/checkerboard composition and
foreground isolation.

| Fixture | Samples | Maximum PNG linear reconstruction error | Maximum native black/white byte error |
| --- | --- | --- | --- |
| Avatar | 1 | 0.003662 | <0.000001 |
| Avatar | 4 | 0.003662 | 1 |
| MMD self-shadow | 1 | 0.003736 | 0 |
| MMD self-shadow | 4 | 0.003223 | 0 |

Thresholds fixed in the driver are 0.005 for linear reconstruction and 2.1
byte levels for native composites. The 16-image contact sheet was visually
inspected: no conspicuous silhouette fringe, outline halo, cutout edge or
hair-compositing defect. Single-sample jaggies and 4x smoothing are visible
as expected. No renderer or shader change was needed. Captures, raw linear
RGBA, logs and `summary.json` stay in the ignored build directory.

## Bounded tangent comparison and stop

Before capture, [validation issue 105](https://github.com/animu-sphere/hydra-toon/issues/105)
fixed a 15-minute capture/inspection budget and this existing small set:

- `adapters/hydra2/tests/preview-reference.usda` with the existing
  PreviewSurface driver: generated mirrored rest frames against Storm.
- `adapters/hydra2/tests/skinning.usda`, through the existing Hydra primvar
  tests: authored/generated frames, mirrored seams and skin/morph deformation.
- The existing core tangent test's independent CPU-normal oracle.

The unchanged PreviewSurface reference driver ran once, with no case-list
extension, and the tangent/primvar selection passed 5/5 including the new
RGBA fixture. Capture and visual inspection completed within the fixed
budget. Across 48 comparisons, 36 sensitivity checks and 55 independent
controls, all declared criteria passed. The mirrored normal map has RGB MAE
0.722575/255 and p95 maximum-channel error 4 at both sample counts. The baked
rotation control has MAE 0.727729/255 and p95 4. The Toon and Storm mirrored
normal-map images were also visually inspected without an inverted patch or
conspicuous seam defect.

`reference_equivalent` remains false: intermediate metalness has MAE
14.719618 and p95 35; transformed-normal coordinates have MAE 35.320206 and
p95 83. Their semantic causes and acceptance are already recorded in
[report 75](75-2026-10-18-preview-surface-reference.md), with the extended
reference set in [report 76](76-2026-10-18-preview-surface-extended-reference.md).
Remeasuring those differences does not justify another suite or shader change.

Authored external-asset tangents, external deformed-frame/glTF-engine
comparisons, tangent morph deltas and CPU-deformed generated frames remain
unverified or unsupported. Authored/generated deformation here is covered
by analytic CPU/GPU oracles, not external equivalence. No visible defect
was found in the implemented path, so further comparison stops under
material policy section 12.1. Reopen only for a concrete visible defect,
frame semantic change or reproducible recurrence; do not continue asset search
to close this release.

## Host boundary disposition

[Report 82](82-2026-10-19-usdview-rgba-consumer.md) establishes the controlled
linear-framebuffer consumer and measures the native usdview transparent sRGB
boundary defect. Native transparent sRGB display/export is an accepted
unsupported host path for this release. The controlled conversion does not
repair it. Use the viewport foreground PNG or an explicit linear-AOV consumer
conversion; do not advertise native transparent screenshots as supported.
Arbitrary hosts, full textured-avatar Hydra-AOV acceptance, other GPUs and
devices without `alphaToOne` are outside this bounded evidence. Quantized
linear RGBA8 retains limited precision at low alpha.
