# Hydra premultiplied RGBA output

- Date: 2026-10-18
- Machine: Windows x86_64, NVIDIA RTX A5000
- Build: MSVC 14.51; canonical CY2026 OpenUSD 26.08 `lookdev`, combined
  `viewport-usd`
- Scope: the Hydra setting and colour AOV boundaries of the
  [output policy](../../design/RENDER_OUTPUT_POLICY.md), following
  [offscreen report 78](78-2026-10-18-offscreen-rgba.md)

## Change and interpretation

The render delegate exposes `toon:backgroundMode`, a string or token with
`opaque` and `transparent` values, and `toon:backgroundColor`, a linear-sRGB
float4 with finite components in [0,1]. The default is opaque
`(0.05, 0.10, 0.15, 1)`. Opaque ignores the fourth component and clears alpha
to one; Transparent clears zero RGBA independently of the stored colour.
The setting pair is applied atomically at pass execution. Invalid types,
mode names or colour values warn and retain the last accepted background,
including across renderer recreation on MSAA edits. Backend rejection,
including the offscreen unsupported-`alphaToOne` restriction, reports an
error and leaves the AOVs unconverged.

The colour AOV is RGBA8 UNORM, linear sRGB with linear transfer and
premultiplied alpha. The CPU buffer flips to bottom-row-first and resamples
without changing channel interpretation. There is no straight-alpha or
display-encoding conversion in this boundary. A host needing one must
convert explicitly. Renderer background settings own the clear even if
the AOV binding has a different clear hint. Scene, material and lighting
values are not changed by background selection.

## Controlled evidence

`toon-renderer-hydra-rgba-gpu` uses an original in-memory USD triangle and
emissive PreviewSurface material through UsdImaging and the actual Hydra
render pass, at actual 1x and 4x MSAA. Its mapped colour buffer is compared
byte-for-byte to a separately rendered offscreen product after accounting
for row orientation. Checks cover:

- Default opaque clear, zero transparent clear and quarter-opacity Blend.
- Analytic premultiplied RGB versus alpha at every pixel, including partial
  silhouette coverage at 4x, and independent interior opacity expectations.
- Source-over recomposition of the transparent product over a non-default
  solid background versus separately rendered opaque output, within two
  UNORM levels per RGB channel; every opaque-output alpha is one.
- Transparent foreground bytes unchanged by colour selection or returning
  from opaque mode; scene revisions unchanged by background settings.
- Invalid mode/type/range/NaN rejection, accepting both string and token
  modes, and retaining the accepted pair across MSAA renderer recreation.
- A separate half-size depth AOV, untouched by Blend, and a conspicuous
  host AOV clear hint that must not replace the renderer clear.
- USD opacity edits to opaque and zero opacity, verifying foreground alpha
  one and zero respectively through the same Hydra pass and AOV.

## Verification and remaining boundaries

The combined `viewport-usd` build passed. Targeted CTest selection
`hydra|delegate|plugin|usdview|rgba` passed 14/14, including the actual
`testusdview` host smoke and existing offscreen RGBA checks, with the lookdev
runtime's `bin` and `lib` on `PATH`. `python scripts/check_docs.py` and
`git diff --check` passed.

This run establishes the mapped colour AOV contract, not a host display or
PNG export convention. Viewport product compositing, host display/export
conversion, Hydra textured/outline/Mask fixtures, the full bounded fixture
and background set, and external tangent comparison remain outside this
run. The optional-feature rejection branch was not GPU-validated on a
device lacking `alphaToOne`. No release was published.
