# Sparse GPU morphs before skinning

Normal-offset ingestion and rest-normal fallback are evaluated subsequently
in [renderer report 35](35-2026-10-05-morph-normals.md).

- Date: 2026-10-04
- Machine: Windows 11 x86_64, NVIDIA RTX A5000; Vulkan loader 1.4.321,
  device API 1.4.329; MSVC 19.51; OpenUSD 26.08, CY2026 lookdev runtime
- Scope: the GPU morph foundation of [v0.3.0](../../roadmap/v0.3.0.md),
  evaluated in core, offscreen, Hydra and native presentation paths

## State and GPU routing

Sparse rest-space position/normal offsets and per-point ranges carry a
structural revision, independently of the small weight array. The vertex
stage applies morphs before the geometry bind and skinning transforms in
Unlit, MToon Opaque/Mask, Blend and inverted-hull pipelines. Zero, negative,
fractional and multiple weights use the same shaders. A missing weight
index contributes nothing; an empty weight array disables morphing. The
descriptor range uses the current weight count even when buffer capacity
is larger after a shrink.

`toon-morph-state` checks that changing weights preserves the points,
normals, topology, skin, pose and target arrays/revisions, and that identical
or non-finite weights and malformed ranges change nothing. Too-short ranges
disable morph evaluation for topology that reaches past them. Snapshot
structural arrays remain shared and immutable.

## Offscreen oracle

`toon-morph-gpu` compares two persistent renderers at 96×96 and 1x sampling:
one evaluates sparse targets on the GPU, the other receives independently
CPU-deformed rest points and normals with the same skin binding. A
nonidentity geometry bind and rotating joint test deformation order.
Front/back triangles exercise hulls as well as surfaces.

There are 36 animated frames in each of eight combinations: with/without
skinning and Unlit/Opaque/Blend/Mask. All 288 colour payloads match byte for
byte; every depth sample differs by at most 1e-6. Vulkan validation reports
zero messages. Each combination uploads points, topology and targets once,
creates four pipelines once, and writes weights 30 times; six empty-weight
frames disable the morph without writing a buffer. Weight-only frames
change no geometry, skin, pose, material, target allocation or pipeline
counter. Authored normal offsets are included in the CPU oracle.

Morphed hulls conservatively bypass rest/joint-envelope culling, and morphing
meshes cannot establish opaque-triangle coverage: those envelopes describe
the rest points, not arbitrary signed morph displacements. This preserves
visibility at the cost of retaining those hull submissions.

## Hydra and viewport

`toon-renderer-hydra-skinning` drives the stage scene-index chain at time
codes 1, 2, 2.5 and 3. The pose edit changes only the pose revision; the
blend-shape edits change only weights. At weight 0.5, the authored
inbetween moves point 0 by 0.75 in z; at weight 1 the target moves it by 1.
Rest points and target revisions stay unchanged. The dual-quaternion quad
continues through usdSkelImaging's CPU fallback.

`toon-viewport-morph` captures nine native swapchain frames at time codes
1 through 3 in increments of 0.25, at the default 4x sampling. A constant
pose and sparse two-point target deform and return: the first and last
captures have identical SHA256, and the middle differs. The session reports:

```text
topology=1 points=1 materials=1 textures=0 skins=1 poses=1
morphs=1 morph_weights=9
```

The one material is the Hydra fallback. Targets, rest geometry and skin
stay resident. Captures perturb frame timing; this run establishes routing
and images, not input-to-display latency. The live upload panel and Hydra
frame evidence expose the new counters too.

## Reproduction and limits

```sh
ost build --profile core --jobs auto
ost test --profile core
ost validate --profile core
ost build --profile lookdev --intent viewport-usd --jobs auto
ost test --profile lookdev --intent viewport-usd
ost validate --profile lookdev --intent viewport-usd
cmake -S . -B build/morph-no-vulkan -G "Visual Studio 18 2026" -DTOON_ENABLE_VULKAN=OFF
cmake --build build/morph-no-vulkan --config Release --parallel
ctest --test-dir build/morph-no-vulkan --build-config Release --output-on-failure
```

Core has eight passing CTests; viewport-usd has 37, including the usdview
host and native presentation regressions; Vulkan-free core has seven.
Both OST targets pass validation. Core-only Hydra/viewport checks and
unpackaged artifact integrity remain explained skips.

The Hydra adapter consumes position targets only. Normal-offset ingestion,
and the treatment of meshes lacking normal offsets, remain separate work;
authored or rest-derived normals currently retain their rest values under
Hydra position morphs. The core/GPU path accepts explicit normal offsets.
This is not yet a direct expression path that bypasses Hydra sync, late
MotionPose latching, animation diagnostics or latency telemetry. No avatar
expression-fidelity or motion-to-display latency claim follows from these
controlled fixtures.
