# Lit display-colour fallback

- Date: 2026-10-18
- Machine: Windows x86_64, NVIDIA RTX A5000, driver 597.16
- Build: MSVC 14.51; canonical CY2026 OpenUSD 26.08 `lookdev`, combined
  `viewport-usd`; plain CMake without OpenUSD
- Scope: unbound meshes and subsets, following
  [report 71](71-2026-10-18-material-fallback.md)

## Cause and behaviour

A local Kitchen Set opened in usdview appeared unshaded. Inspection of its
composed stage found 1,788 meshes, all without bound materials; 1,784 carry
display colour and none author normals. Its previous route returned the
mesh colour directly from the unlit shader. Having PreviewSurface support
did not help an asset without PreviewSurface materials.

An unavailable material binding now selects the existing PreviewSurface
pipeline with mesh display colour as the linear base colour: metallic 0,
roughness 1, opaque, double-sided, no textures or emission. Geometry normals
are read or generated by the existing mesh path. Scene direct lights and
diffuse uniform ambient apply; a scene without supported lights uses the
existing camera key and 0.25 ambient. The adapter still reads constant
display colour only and uses grey when unavailable.

The fallback is a local draw description, not a scene material. A flag
changes the interpretation of three otherwise unused push-constant scalars
to RGB and skips the material-buffer lookup. The shared constants remain
128 bytes. No new pipeline, descriptor binding, parameter-buffer layout,
per-mesh material slot or USD authoring is required. Colour edits change
draw constants; lighting edits use the existing frame buffer.

Unreadable **bound** materials retain opaque unlit magenta and depth writes.
Readable material selection, including MToon and MMD priority, is unchanged.
The contract is [material policy §12](../../design/MATERIAL_POLICY.md#12-previewsurface-and-generic-usd-fallback).

## Controlled checks

At 1x and 4x MSAA, `toon-preview-surface-gpu` checks:

- An unbound back face is opaque black with no illumination and writes depth.
- A front-facing surface matches an independent normal-incidence dielectric
  BRDF at roughness 1, within two UNORM levels on every RGB channel.
- Changing mesh colour changes that response on all three channels.
- Moving the direct light behind the surface removes the direct response.
- Ambient alone matches `base * 0.96 * 0.25`, within two levels.
- Colour and light edits upload no points, topology or textures, write no
  material slot and create no pipeline. Vulkan validation remains clean.

`toon-renderer-hydra-material-fallback-gpu` exercises an actual in-memory USD
mesh with an emissive PreviewSurface subset, an unsupported-material subset
and an unbound face. In darkness, the unbound face is black, while emission
and magenta remain visible. At direct strength 10, the unbound face lights
and magenta remains exact. Repairing/reverting the unsupported graph still
restores Blend/opaque depth behaviour and writes only the two changed
material slots, retaining static resources.

The headless bootstrap and skinning checks now compare their display-colour
pixels against an independent CPU BRDF for the default camera key and
ambient, rather than the previous unlit-colour thresholds.

## Local usdview evidence

The local Kitchen Set was captured with the previous installed hdToon and
the current build, using the same authored session camera, 800x600 extent,
4x MSAA and sRGB display correction. Only the session camera was authored;
the source asset was unchanged. The worker asserts every mesh is unbound
and each capture reports 1,788 draws, nine pipelines, one material write
(the host fallback Sprim) and zero textures. It records the loaded plugin
path and OpenUSD version separately for each run.

The new image visibly shades curved and differently oriented surfaces.
79,388 pixels differ by more than two RGB levels between captures. This is
a before/after sensitivity observation, not an external-renderer parity
measurement. Captures, worker, metadata, frame evidence and image hashes
remain local under `build/display-color-lighting/`; the asset and images
are not redistributed in the repository.

## Verification and limits

Built both trees using the MSVC developer environment, then ran
`ctest --test-dir <tree> --output-on-failure`:

- Combined `viewport-usd`: 61/61 passed, including Hydra, GPU, usdview,
  viewport presentation, headless evidence and installed consumers.
- Plain CMake without OpenUSD: 18/18 passed.

The combined test process puts the lookdev runtime's `bin` and `lib` on
`PATH`. Changed documentation links and `git diff --check` passed.

This adds surface shading, not environment reflections, shared cast
shadows, contact shadows, per-vertex display colour or mesh display-opacity
support. Those boundaries are unchanged. No release is published.
