## What changed

`hdToon` now reads nine MToon texture roles. Emissive joins base colour,
shade, MatCap and rim multiply as sRGB colour. Normal, shading shift and
UV animation mask join outline width as linear data. The adapter reads the
normal and shading shift roles' contribution `scale` separately from their
UV transform. Each role keeps its own offset, rotation, nonuniform scale
and wrap. An image is still shared by path and encoding and released with
its last material reference. Metallic/roughness and occlusion are not
inputs to MToon's lighting model and are left unread.

Emission multiplies its factor, including the already-applied strength, by
the emissive texel. Shading shift adds linear R times its contribution
scale; an absent image adds zero. Normal maps decode tangent-space XYZ,
scale XY and use a tangent frame derived from deformed view-space positions
and the original mesh UVs. Authored normals remain the frame's normal,
skinned with the points; absent images, absent UVs and degenerate UV
gradients retain that normal. The mapped normal is reversed on a back face.
The outline extrusion continues to use vertex normals rather than a
fragment normal map.

UV animation samples the mask's linear B through its own unanimated
transform. That value multiplies each speed. Rotation about the UV centre
comes before scroll, then each sampled role applies its own texture
transform. MatCap remains view-mapped and unanimated. The outline vertex
stage samples both mask and width at explicit mip zero. These choices use
the [MToon 1.0 specification](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_materials_mtoon-1.0/README.md#uv-animation),
including its U-right, V-down rotation matrix and transform order.

`RenderWorld::SetTimeSeconds` carries host evaluation time through the
snapshot and draw list. Hydra exposes the same value as `toon:timeSeconds`,
zero until the host supplies it. The viewport supplies its selected USD
time code divided by the stage's `timeCodesPerSecond`, including at an
animated stage's start. Time changes update a separate 16-byte GPU frame
buffer; they rewrite no material slot or geometry. The material slot grows
from 352 to 544 bytes, and the draw push constants stay at 128 bytes. The
pipelines and shared texture table stay fixed.

## Viewport time-code route

The committed `adapters/viewport/tests/mtoon-uv-animation.usda` uses a
self-authored 2x2 colour texture, one emissive MToon quad and 30 time codes
per second. Thirty-one frames select time codes 0 through 30 with a step of
1. The final image samples green, matching a static offset of 0.5 in
`mtoon-uv-reference.usda`, byte for byte, at 256x256 and 4x MSAA. Both runs
select one MToon mesh with authored normals and one texture. The animated
run uploads one topology, one point array, two material slots (including
the delegate's fallback) and one texture; all subsequent time moves upload
nothing. Each run reads back only its final capture.

These fixtures require the session's `vrmSchema` and `vrmImaging`, which are
not dependencies of the regular CTests. They were run with the existing
published plugin paths registered in `PXR_PLUGINPATH_NAME` and their DLL
directories on `PATH`, using the freshly built viewport:

```sh
<build>/adapters/viewport/toon-viewport --hidden --vsync off --overlay off \
    --usd adapters/viewport/tests/mtoon-uv-animation.usda \
    --time 0 --time-step 1 --frames 31 --expect-draws 1 \
    --width 256 --height 256 --screenshot build/mtoon-uv-animated.ppm
<build>/adapters/viewport/toon-viewport --hidden --vsync off --overlay off \
    --usd adapters/viewport/tests/mtoon-uv-reference.usda \
    --time 0 --frames 1 --expect-draws 1 \
    --width 256 --height 256 --screenshot build/mtoon-uv-reference.ppm
cmake -DFIRST=<absolute animated capture> -DSECOND=<absolute reference capture> \
    -P adapters/viewport/compare_captures.cmake
```

## Animated avatar

The same local AliciaSolid retargeted VRMA 01 stage used in report 24 was
drawn for 120 frames, from time code 0 by steps of 0.25, at 800x900 and 4x
MSAA. It draws 20 MToon meshes, all GPU-skinned and using authored normals;
five transparent surface draws and fifteen hulls. Its 12 MToon materials,
one fallback and seven textures upload once: 20 point/topology/skin uploads,
13 material writes, seven texture uploads and 2,400 pose writes. There are
no validation messages and one final capture readback. This avatar's
existing texture use does not exercise every newly added role; the
controlled tests above do. The model, motion and capture remain local.

## Build and validation

```sh
ost build --profile lookdev --intent viewport-usd --jobs auto
ost test --profile lookdev --intent viewport-usd
ost validate --profile lookdev --intent viewport-usd
ost build --jobs auto
ost test
ost validate
```

The `viewport-usd` CTests pass 26/26 and the `core` CTests pass 4/4.
Both `ost validate` runs pass. Direct CTest execution of a Hydra-enabled
viewport needs the runtime's `bin` and `lib` on `PATH`, even for its
bootstrap tests; `ost test` supplies them. The local store was selected with
`OST_HOME=C:/Users/snkm/.ost` in this execution environment.

## Limits

Only the mesh's supported vertex/varying `st` set is read; other texture
coordinate sets sample nothing, except MatCap which uses no mesh UVs.
Face-varying UVs and normals and authored tangents are not added. The
derived tangent frame is not an assertion of MikkTSpace equivalence on all
UV seams. Time is an absolute selected evaluation time, not an integrated
history of changing speed factors; the viewport still has no wall-clock
playback. `usdview` hosts must supply `toon:timeSeconds` for UV animation.
Full reference-renderer reproduction, scene lights and the remaining
outline/anti-aliasing quality evaluation stay in the v0.2.0 roadmap.
